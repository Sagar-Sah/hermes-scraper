# Hermes update — October 13, 2026

This package contains the current Hermes source and built dashboard. It includes the **Product diagnosis** page and a WSDisplay login-gate check. It does not include local supplier sessions, passwords, API keys, or the product database.

## Find Product diagnosis

Open Hermes at `http://127.0.0.1:18877`. In the **left sidebar**, under **WORKSPACE**, click **Product diagnosis**. It is between **Product explorer** and **Sources & AI**. On a narrow window, click the menu icon at the top left to reveal the sidebar.

On that page, **Step 1 — Sign in to the supplier** opens Hermes's own supplier browser. Sign in there, not in an unrelated Chrome tab. **Step 2 — Analyze a product URL** accepts the supplier product link. The WSDisplay page can show a public description while hiding prices until sign-in; Hermes now reports that login requirement instead of treating it as a complete quote.

## Install or update

1. Stop the old Hermes server.
2. Back up its `data/` directory and any `.env` file. They hold the product database, saved supplier browser sessions, and local settings. Keep them private.
3. Extract this ZIP to a new directory. If replacing an existing installation, copy its backed-up `data/` and `.env` into the new `product-crawler/` directory. Do not overwrite them with files from this ZIP.
4. On macOS or Linux, open a terminal in `product-crawler/` and run `./scripts/start-local.sh`. The first run installs the locked Python dependencies and Playwright Chromium. Node.js 20+ and Python 3.11+ are required. The dashboard is already built in `frontend/dist/`.
5. Open `http://127.0.0.1:18877` and use a hard refresh if an older dashboard remains cached.

The update does not make arbitrary supplier sites automatically extractable. A supplier may require sign-in, present custom controls, block automation, or omit public prices. Product diagnosis shows the observed page and limitations before a harvest is started.
