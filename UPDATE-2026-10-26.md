# Collection tray, product ZIPs and compact archives

The package button at the upper left of Hermes opens a collection and download
tray. Newly completed products animate a package entering a box. Existing
completed products do not generate a notification merely because the page loads.

Completed products are selected by default. Unfinished products require an
explicit warning override, individually or for all unfinished products. Exports
package each selected product in its own ZIP folder with all saved rows, safe
metadata and downloaded images. Missing images and incomplete scope remain
explicit. No new supplier requests are made by exporting.

Supported browsers can choose a destination folder and stream the ZIP there.
Other browsers use a normal ZIP download followed by explicit save confirmation.
Only then does Hermes offer archive selection: all checked by default, select
none, or individual choices. Confirming retains compact archives for checked
products and removes exported working copies. Unchecked products outside the
export are unaffected. Active, changed and campaign-protected work is retained.

Pending exports, discarded ZIPs and retryable file cleanup have durable receipts.
Failed saves, canceled dialogs and uncertain responses do not silently remove
source data. Shared evidence objects are retained when ownership cannot be proved.

See [the collection delivery guide](docs/COLLECTION-DELIVERY.md) for behavior,
browser limitations and API routes.

Validation: 99 backend tests across collection delivery, export, customer CSV,
catalog and storage modules; 26 fully intercepted Chromium UI tests; TypeScript
and Vite build. Fixtures use temporary data and synthetic products. No supplier
scrape, production deployment, live cleanup or running-worker restart is claimed.
