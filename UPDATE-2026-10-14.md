# Hermes scraper performance update — October 14, 2026

This revision reduces browser traversal and export overhead. It preserves supplier pacing, authentication, observed configurations, source-cost records and explicit coverage/verification states.

## Measured changes

| Local workload | Original | Optimized | Scope |
| --- | ---: | ---: | --- |
| Eight exact browser configurations with a branch journal | 50.89 s | 18.93 s | One controlled loopback Chromium comparison simulating the reviewed Printograph readiness contract; identical eight prices, 12 quote requests, 20 observations, 15 completed journal branches and exact finite coverage |
| Large form DOM snapshot | 9.060 ms | 4.515 ms | Synthetic 82-control / 640-radio form; identical full snapshots; medians of alternating trials |
| Catalog CSV/Parquet export, 30,000 rows / 10 products | 4.704 s | 3.870 s | Median of three local synthetic runs; all readable CSV and decoded Parquet contents match |

These results measure local implementation overhead. They do not establish a supplier's throughput or an entire catalog completion time. The browser fixture uses a no-op limiter and in-memory journal; it makes no supplier requests. Reproduction and raw measurements are in `scripts/bench_browser_traversal.py`, `docs/performance-baseline-20261014.json`, `docs/performance-optimized-20261014.json`, and `docs/browser-snapshot-performance.md`.

## Browser traversal

The option walker previously repeated the same 700 ms stability wait during consecutive checkpoint, restore and branch bookkeeping calls. On reviewed Printograph product types 1, 27 and 36, an already settled form can now reuse its certification for up to one second, after reading the current DOM again. A different control/price/service signature, navigation, selection, counted request, completed source response or observed busy state invalidates it. Reuse never extends its age. Direct price publication and the bulk table's anchor quote retain full stability waits; no source quote or numeric price is cached by this change. Unknown sites retain their original settling behavior: a local 1.8-second delayed-price regression demonstrated why the shortcut cannot be enabled universally. The stability helper is included in the durable journal's code scope, so its behavior changes cannot silently reuse older branch markers.

Each DOM observation also reuses visibility, labels and selector paths within that synchronous read. The caches are discarded before the next read, so dynamic controls and prices are observed afresh.

## Exports

Catalog exports reuse each row's customer and audit projections across combined and per-product files. The process retains bounded memory, atomic manifest publication and separate readable CSV / evidence-preserving Parquet output. Export measurements and parity checks are documented in `docs/export-performance.md`.

## Concurrent products

The scheduler allowed 100 product tasks, but browser extraction silently defaulted to one page. The new default is four active browser workers. `ATLAS_BROWSER_PRODUCT_CONCURRENCY=99` permits a larger worker pool after restart, bounded by `ATLAS_PRODUCT_CONCURRENCY` (default 100). The local launcher now reads `.env`, and Sources & AI / run details report configured capacity, active workers and workers waiting for browser admission.

For the user's workload of 99 products spread across several suppliers, merge the two settings in `examples/99-product-workers.env` into the existing `.env`. They set both task and browser capacity to 99. Preserve the existing credentials, data directory and supplier profiles. The default for a new installation remains four; the 99-worker profile is explicit.

Source admission happens before a browser worker starts navigating. The existing per-source concurrency ceiling also bounds resident extraction pages for that origin, so 99 jobs for one supplier wait outside browser execution while other suppliers can use free global slots. Supplier request rates, concurrency ceilings and adaptive backoff are preserved. Local asynchronous scheduling tests cover 99 queued tasks, mixed origins, caps, cancellation and permit cleanup; this is not a benchmark of 99 simultaneous Chromium pages or live supplier capacity. Existing `.env` files with an explicit value of 1 keep that override until edited.
